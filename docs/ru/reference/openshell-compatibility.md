# Совместимость с OpenShell

cautem реализует часть контракта OpenShell на Docker и Podman. Основа сравнения — коммит OpenShell `a0814443f19c07102b19ff09d6ead3d3ba59f9c5`. Совместимость пока частичная. Kubernetes и microVM в эту проверку не входят.

В gateway есть обработчики всех 74 публичных методов закреплённого gRPC-сервиса. Тесты проверяют регистрацию методов, форму сообщений, маршрутизацию авторизации и вызовы с ограничением времени. Это подтверждает доступность методов, но ещё не совпадение результата для каждого входа и backend.

В CLI есть обработка всех 16 команд верхнего уровня из закреплённого исходника OpenShell. Это проверка только названий: совпадение вложенных команд, параметров, вывода, ошибок и поведения SDK ещё не подтверждено.

Остаются пять направлений проверки:

| Область | Что нужно подтвердить |
| --- | --- |
| Конфигурация | Значения по умолчанию, приоритет источников, пустые значения, валидация и фактический эффект каждого поля gateway, политики, профиля и шаблона. |
| CLI и SDK | Команды, параметры, переменные окружения, вывод, ошибки и потоки на исходных примерах закреплённой версии OpenShell. |
| Supervisor | Полное совпадение событий, сигналов, дочерних процессов, завершения и финализации при перезапуске и восстановлении соединения. С OpenShell gRPC relay Linux отправляет события основного процесса и найденных через `/proc` потомков; `SIGCHLD`/`wait4` ускоряют локальное обнаружение выхода основного и усыновлённых процессов, а опрос раз в 250 мс остаётся резервным. Relay ждёт пачку до 25 мс; сетевое время и повторные попытки не дают гарантировать доставку в gateway за 250 мс. Короткие процессы, собранные родителем, и замены через `exec` всё ещё могут быть пропущены; полный parity при restart/reconnect остаётся открытым. |
| Расширения gRPC | Поведение отдельных методов, передача данных внешнему compute driver, ошибки, таймауты и отмена в middleware и interceptors. |
| Опубликованные модули SDK | Автономная сборка потребителя SDK из выпущенных версий без локальных замен workspace. |

CLI `v0.1.6` собирается с опубликованными зависимостями при `GOWORK=off`; проверки релизных архивов и установщика для Linux, macOS и Windows прошли. Прежняя ошибка изолированной сборки CLI устранена, но это само по себе не подтверждает автономную работу SDK или полное совпадение команд с OpenShell.

[Реестр совместимости gateway](https://github.com/cautem/cautem-gateway/blob/main/internal/httpapi/testdata/openshell_compatibility_gaps.json) содержит проверенные участки и открытые задачи для этого коммита. Статус `verified` относится только к названному участку. Перед общим заявлением о совместимости реестр нужно сверить с текущим кодом и результатами запуска.

Для локальной проверки версии протокола и реестра выполните `task compat:pin-check`, `task compat:proto` и `task compat:gaps`. Проверка не позволит удалить ни одно из 14 уже учтённых требований, но не обнаружит требования, которые ещё не внесены. Поведение нужно отдельно проверять на Docker и Podman: успешная проверка реестра не подтверждает работу backend.
